# Phase B4 — Characters through the pivot (subplan)

Source: `zesty-bubbling-acorn.md`, Plan B / Phase B4, planned 2026-07-24
under the constraints locked in `reflective-stirring-blossom.md`. Puts the
pivot's characters into the running game through the proven A4 MPFB path
(`char_mpfb.py` via `gen_character.py --mpfb` — parametric CC0 body,
authored weights, canonical-skeleton transplant): the shipped monk fixture
becomes the live human, the three KayKit races are rebuilt as themed
characters (penitent/inquisitorial/monastic silhouettes per race
identity), class outfit/tint values retune to the locked VQ-A4 language,
and the carried zone_review flag ("player skin overexposes under the dusk
key") gets a diagnosis-then-fix pass with render evidence.

**Scope boundary — the 2026-07-24 user constraints, verbatim:**
- B4 executes unsupervised to the feel-check boundary. The user feel-check
  owns the gate's final box.
- KayKit source + old race glb deletion is USER-GATED (after look
  confirmation) — the subplan lists it as an explicitly deferred task,
  never executed this block.
- All character builds run the MPFB path (CPU-only, ~30 s each) — the AI
  mesh chain stays rejected (A4.11). No GPU budget exists for B4; if a
  task genuinely needs GPU, mark it stop-and-surface.
- Model-asset autonomy: silhouette/param/asset choices are the planner's +
  workers' to make (penitent/inquisitorial/monastic per race identity;
  human = the shipped monk fixture).
- The overexposure flag is B4 material work: plan a diagnosis task
  (reproduce with zone_review under the dusk key vs gear_render neutral,
  isolate material factor vs exposure) before any fix task; evidence =
  before/after renders, never GUI.
- zone_review's hardcoded `PLAYER_GLB = content/models/human.glb` must
  follow the swap — decide the clean seam (probably read the race RON's
  model like the game does; state the forced choice from what the code
  shows).
- Standing rules: foreground commands only; §5 comment policy; §7 ONE
  workspace nextest at the B4 gate only; commit per green task, short
  messages, no attribution trailers; content_lint must stay green at every
  commit (VQ-B1/B2/B3/B4 apply to every repointed race).

**B4 does NOT touch:** VFX RONs / telegraph constants / class ability
numbers (B5 owns VFX and emissives); any B2-approved environment value
(SUN_DIR/SUN_COLOR, HDRI, fog, palette — an overexposure diagnosis
pointing there is a stop-and-surface, not a retune); the canonical
skeleton/clip library (`Character.fbx` + `clips/` — durable architecture);
the A4 iteration backlog's elbow-flexion item (accepted caveat, "later,
not now" per the 2026-07-23 ruling — the gate walk may re-raise it);
golden frames (fact 3: no golden scene reads a race RON — no regeneration).

This file breaks the phase into 9 single-agent tasks plus one deferred
user-gated task and the gate. The orchestrator dispatches one agent per
task, verifies with the given command (never prose), commits on green, and
strikes the checkbox. Order is the listed order and it is load-bearing:
B4.1 (monk swap) before B4.2/B4.3 — evidence work must render the
character that will actually ship; B4.2 (zone_review seam) before B4.3
(diagnosis renders the swapped player); B4.3 before B4.4 (no fix without a
diagnosis); B4.5 (preset seam) before B4.6–B4.8 (the builder cannot
express a second race today — fact 5); B4.9 (tints) after the races (tints
are judged against the installed bodies); B4.D never runs this block.

Tiers (campaign routing table): **fable** = art-direction judgment + real
design risk (the overexposure diagnosis; the preset-seam design on the
character builder; the three themed-race tasks — garment/macro curation
judged on rendered sheets is exactly per-prop selection's class of work);
**sonnet** = the rehearsed swap, the zone_review seam, the conditional
material fix, and the band-mapped tint retune (B3.9 precedent: recolors
mapped from the locked VQ-A4 table are sonnet work); nothing here is
haiku-worthy. Per-race preset verdicts are recorded in this file's
**Decision log** (A2.8/A3.12/B3.4 precedent).

**Shell discipline (all tasks): FOREGROUND commands only** — background
shells die silently on this box (3× precedent). Builds are ~30 s CPU;
nothing here needs a long timeout beyond cargo compiles (~10 min explicit
timeout on first release builds of offscreen bins).

   comment hygiene.

   rest is untouched.** Grep of `human.glb` across `*.rs`: only
   `client/vordar-client/src/body.rs:213`

   `human_gen.glb`) read the REAL content dir; both flip in the same

   `"Race": (id: "human")`; no class/race picker exists (todo.md Phase C
   note holds). dwarf/elf/valkyrie are content-ready-but-unspawned →
   their swaps are **content-parity work, sized small** — machine-gated
   installs whose only near-term audience is the lint suite, the review
   sheets, and the user's look confirmation for the deferred deletion.
   Not user-visible priorities.
4. **The three KayKit repoints are RON-and-lint work, no code.** Their

   `forward_offset: 3.14159`; MPFB-built glbs carry the 10-action Mixamo

   `idle/walk/run/attack_slash/death/hit`, sets `forward_offset: 0.0`,

   pins those races' clip names; `content_lint.rs` walks every race RON
   data-driven (`race_clips_exist_in_gltf`, `race_models_within_budgets`,
   `race_models_expose_sockets`, texture caps) — THE machine gate per
   race.
5. **The builder cannot express a second race today.** `char_mpfb.py`
   hardcodes `MACROS`/`SKIN`/`GARMENTS`/`EYES` as module constants (the
   monk fixture), and `gen_character.py --mpfb` rejects subject/seed and
   always writes `cand_mpfb/`. A preset seam is required engineering
   before any themed build. Measured chain cost: 30.4 s wall CPU
   (idempotent resume 0.16 s); `MPFB_MAX_DIM = 1024` byte-cap ruling
   applies to every preset (16 MB VQ-B2 evidence in a4.md).
6. **Wardrobe on disk (probed in the MPFB user data dir):** two packs
   installed (`makehuman_system_assets`, `suits02` — `packs/*.json`
   enumerate membership, so per-asset pack verification is
   machine-checkable). Garments: 4 donitz monk-robe variants (`_hood`,
   `_hood_down`, `_hood_off`), rehmanpolanski viking tunic/pants/boots,
   culturalibre hero/heroine suits 1–3, male/female casual+elegant suits,
   matcreator sci-fi armor (off-register), shoes 01–06, fedoras; hair ×10
   (afro/bob/braid/long/ponytail/short); full skin matrix
   (young/middleage/old × 3 ethnicities × m/f). CREDITS row for suits02
   enumerates only the 4 donitz robes as "assets used" → **any new
   garment/skin/hair use must extend the row's enumeration (and verify
   membership in a Cleared pack's listing) in the same commit — the
   ledger never lags use.**
7. **The overexposure flag was raised on the WRONG body.** zone_review's
   `PLAYER_GLB` is the old `human.glb` — the untextured near-white VRoid
   mannequin (A4.11: "untextured white mannequin") — rendered under
   `TestLight { SUN_DIR, SUN_COLOR: (1.5, 1.38, 1.2), ambient: 1.0 }`
   plus the zone HDRI's IBL. A near-white albedo overexposing under a
   1.5-energy key is expected behavior for that placeholder. The flag
   must be re-evidenced on the swapped textured monk before any fix —
   it may dissolve outright. SUN/HDRI/fog values are B2 user-approved:
   out of bounds for any fix.
8. **zone_review seam — the forced choice, from the code.** The bin
   already links `vordar_game` (`load_zones` at line 24) and the game
   resolves the player mesh through `RaceLibrary::load_dir` →
   `.model("human").asset` (`race.rs:123`, consumed by
   BodyComposeSystem). Reading the race RON through that same API is the
   game's own resolution path with zero new dependencies; the only
   alternative is another hardcoded const, which is exactly what just
   went stale. Forced: the const dies, `RaceLibrary` reads it.
9. **Tint mechanics probed.** `ClassDef.tint` (class.rs:54) multiplies
   the skinned mesh color; the SDF `outfit` array is dead for glTF races
   (fallback-only, class.rs:50 comment). Current tints are pre-pivot
   authoring: human `(0.66, 0.80, 1.0)` steel-cyan (rhymes with a
   focus-crystal outfit that no longer renders), ravager
   `(1.0, 0.55, 0.48)` ember. A strong multiplier over the authored CC0
   robe textures repaints them — retune must stay subtle (identity-cast,
   not repaint) and sit inside VQ-A4's roles.
10. **Height is a proven per-build seam.** `bake_height`/`--height`
    scales the armature object uniformly (clips play on the canonical
    skeleton unchanged — A4's units invariant); `gen_character.py
    --height` threads it. Current content normalizes everything to
    1.744 m; modest race variation (short dwarf, tall valkyrie) is a
    uniform scale, safe by construction, judged on sheets.
11. **The female path is untested.** `create_human` has only ever run
    with `gender: 1.0`; garment auto-fitting on a `gender: 0.0` basemesh
    (valkyrie, possibly elf) has never been exercised. A bad fit/clip
    result is candidate data (build another variant), not something to
    patch in the fitter; if no variant fits, stop and surface with the
    sheets.
12. **Suite deltas at the gate are exactly two assertions.** Beyond fact
    2's two flipped tests, the workspace suite has no other race-swap
    consumers: `hit_react.rs:340` and `body.rs` synthetic tests build
    their own components, class.rs tests read classes (untouched fields),
    UI snapshots and goldens read no race RON. A gate failure outside
    those two files is a real regression, not a baseline to move.
