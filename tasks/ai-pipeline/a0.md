# Phase A0 — Infrastructure + Governance (subplan)

Source: `zesty-bubbling-acorn.md`, Plan A / Phase A0 (5 numbered items). This file
breaks those 5 items into 13 single-agent tasks, ordered by dependency. The
orchestrator dispatches one agent per task, verifies with the given command
(never a GUI), commits on green, and strikes the checkbox.

Tiers are the cheapest model that can do the job: **haiku** = mechanical
download/run/verify; **sonnet** = ordinary scripting/config/research;
**opus** = hard integration carrying real design/engineering risk.

Tool installs (ComfyUI, TRELLIS) live **outside the repo** at `C:\tools\` — no
existing AI-tool convention was found on this machine (`C:\StableDiffusion`
is a stale 2022 latent-diffusion checkout, not a live pattern; `C:\Dev` is
IDE/Maven-only). `C:\` has 384 GB free; the ≤100 GB model budget fits with
room to spare (tally below).

## Divergences from the literal phase-spec wording (flagged per project policy — not silently patched around)

1. **Pano "LoRA" → full SDXL fine-tune checkpoint.** No community SDXL pano
   *LoRA* has a confirmed clean license (Civitai entries carry no explicit
   license grant). `ProGamerGov/sdxl-360-diffusion` is a full SDXL-base
   fine-tuned checkpoint, not a LoRA — it satisfies the *intent* (license-
   defensible, SDXL-family, pano-specialized) better than an unlicensed
   LoRA. Its own HuggingFace license field is empty; verdict is **pending**,
   not cleared (task A0.9 below). Flag this explicitly to the user before A2
   generates anything with it.
2. **DiT360 is blocked**, not "an alternative" as the source plan assumed.
   Its adapter is MIT, but it's trained on top of **FLUX.1-dev**, which the
   plan itself already excludes as non-commercial. A clean adapter license
   doesn't clear a non-commercial base-model dependency. Ledger verdict:
   blocked.
3. **Turntable tool: `<glb>` only, not `<glb-or-zone>`.** Zone-level
   rendering (parsing `zones.ron`, loading ground/props/skybox as a scene)
   is a materially bigger feature with no A0 consumer — YAGNI'd out of this
   phase. The CLI shape below reserves the dispatch point (branch on file
   extension) so a later phase can add it without a rewrite.
4. **No speculative "shared post-processing helpers" module.** The source
   plan's item 3 mentions helpers "reusing the existing scripts" alongside
   `comfy_run.py`. There is no concrete second consumer yet (that's A1+), so
   no abstraction is created in A0 — `comfy_run.py` is the whole of item 3's
   scope. Add shared helpers when a second script actually needs them.

- [x] **A0.12 — Turntable render tool** `[opus]` — done 2026-07-18 (+ AABB framing beyond spec; verified on human.glb, suite green). Post-rebase note: the bin is feature-gated — invoke with `cargo run -p engine-renderer --release --features offscreen --bin turntable -- <glb> --out <dir> --angles N --size WxH`; camera API consolidated to `set_camera_turntable(min, max, yaw)`. — no dependency (pure Rust, independent of the AI-pipeline branch).

New bin `smirk/engine-renderer/src/bin/turntable.rs`. CLI: `turntable <glb> --out <dir> --angles N --size WxH`. Renders N yaw angles around the asset with the standard HDRI (`content/textures/env/evening_road_01_puresky_2k.hdr`) + a ground quad, writes `<dir>/frame_NN.png` per angle plus one stitched contact-sheet PNG (`<dir>/contact_sheet.png`, frames laid out in a row/grid via the `image` crate, already a dependency).

**This requires two small additions to `smirk/engine-renderer/src/offscreen.rs`** (`OffscreenRenderer` currently has no public way to move the camera or load a real HDRI — both were dropped/kept crate-private after `new()`; a `src/bin/*.rs` target is a separate crate from the lib for privacy purposes, so it can only reach `pub` items):

1. **Camera control.** `OffscreenRenderer::new()` currently builds a local `Camera` and a `camera_buffer`, uses them once to seed the bind group, then drops both (only `camera_bind_group` survives as a field) — so the view is fixed forever after construction. Add `camera: Camera` and `camera_buffer: wgpu::Buffer` as new struct fields (store what's currently dropped), then add `pub fn set_camera_yaw(&mut self, yaw_radians: f32)` that updates `self.camera` and re-writes `self.camera_buffer` via `queue.write_buffer` — same pattern as the existing `set_light`/`set_exposure`. Note: `Camera::recompute_eye()` is `fn`-private to `camera.rs` (not even `pub(crate)`) — the only lever reachable from `offscreen.rs` is `Camera::orbit(yaw_delta, pitch_delta)` (`pub(crate)`, reachable since `offscreen.rs` is in-crate), or add one more tiny `pub(crate)` method on `Camera` itself if a direct absolute-yaw setter reads cleaner than a delta computed from the stored angle. Either is fine; pick whichever is smaller.
2. **Real HDRI environment.** `Environment::from_hdr(device, queue, env_layout, sky_layout, path) -> Result<Self, String>` already exists (`ibl.rs:71`) but is `pub(crate)`. Add `pub fn load_environment_hdr(&mut self, path: &str) -> Result<(), String>` on `OffscreenRenderer` that calls it with `self.env_bgl`/`self.sky_bgl` (mirrors the existing `set_uniform_environment`). Set `renderer.draw_sky = true` (already public) for the sky pass.

**Skinned meshes need a CPU bind-pose flatten before `render_mesh`.** `render_mesh` asserts `data.skeleton.is_none()` — it only drives the static path. `content/models/human.glb` (this task's verify target) **is** skinned (Mixamo rig + 11 clips). Rather than extending the GPU pipeline to draw skinned meshes (real scope creep for a turntable — animated idle/walk turntables are Phase A4's concern, not A0's), flatten to bind pose on the CPU, reusing the existing skinning math verbatim:
```
let rest_pose: Vec<LocalTransform> = skeleton.joints.iter().map(|j| j.rest).collect();
let mats = engine_renderer::anim::joint_matrices(&skeleton, &rest_pose);
```
then for each primitive with `skin: Some(skins)`, replace each vertex's position/normal/tangent with the weighted sum over its 4 joints (`Σ weight_i · mats[joint_i] · v`, renormalizing normal/tangent), and rebuild the primitive with `skin: None`. Set `MeshData::skeleton = None` and `clips = vec![]` before calling `render_mesh`. This works for any glb, skinned or not — no assumptions specific to `human.glb`.

Ground quad: reuse the construction pattern already in `smirk/engine-renderer/tests/offscreen.rs`'s `ground_quad`/`quad_with_material` helpers (not reusable directly — private to the test file — but trivial to duplicate: a handful of `MeshVertex` literals spanning `±extent` at `y=0`). Merge it into the same `MeshData.primitives` vec as the loaded asset so one `render_mesh` call draws both. Assume the input glb is already ground-normalized (true for `content/models/human.glb` per the existing Mixamo pipeline) — no auto-centering logic.

Add the `[[bin]]` entry to `smirk/engine-renderer/Cargo.toml` if not auto-discovered from `src/bin/`.

**Verify:**
```
cargo run -p engine-renderer --release --bin turntable -- content/models/human.glb --out target/turntable-smoke --angles 8 --size 256x256
```
exits 0; then assert 9 PNG files exist under `target/turntable-smoke/` (8 frames + 1 contact sheet) and each is > 2 KB (rules out degenerate all-black/transparent output). No GPU adapter → the tool prints an error and exits 1 (matches the existing harness's "skip cleanly" discipline, though on this dev machine a real adapter is always present).
