Source: `zesty-bubbling-acorn.md`, Plan A / Phase A2 (three-way pano bake-off +
LDR→HDR sun injection). This file breaks that phase into 11 single-agent
tasks, ordered by dependency. The orchestrator dispatches one agent per task,
verifies with the given command (never a GUI), commits on green, and strikes
the checkbox.

Tiers are the cheapest model that can do the job (user ruling 2026-07-18 — no
opus): **haiku** = mechanical download/run/verify; **sonnet** = ordinary
scripting/config/research; **fable** = design-risky work (here: the sun-
injection/RGBE post stage, the circular-padding mechanism, and the bake-off
judgment).

die silently on this box (three prior occurrences). Long generation runs get
an explicit shell timeout (up to 10 min) instead of backgrounding; the ComfyUI
server is launched as a detached OS process via `Start-Process` (not a
backgrounded shell), polled on `/system_stats`, and stopped with
`Stop-Process` when the task ends.

`content/source/CREDITS.md`'s "AI pipeline models" table — sdxl_360_diffusion
**Cleared (conditional)** (MIT stated in README citation block; HF tag still

## Divergences from the literal phase-spec wording (flagged per project policy)

1. **"Offscreen sky/IBL/shadow tests pass with the generated `.hdr`" cannot
   run literally.** Read against the actual suite
   (`smirk/engine-renderer/tests/offscreen.rs`): every sky/IBL/shadow/fog
   test builds a *synthetic uniform* environment via
   `set_uniform_environment` (a 4×2 constant-color equirect) — none accepts
   an external file. They gate the renderer's machinery, not an asset. The
   engine-side gate for a generated HDRI is therefore: (a) a **turntable run
   with the generated file** (`load_environment_hdr` → `EquirectImage::decode_hdr`
   → f16 upload → full IBL bake → sky + lit render — the entire consuming
   path, end to end), plus (b) **analytic file checks** in `hdr_post.py`
   calibrated against the two committed CC0 references (stats below), plus
   (c) the unchanged full suite at the phase gate. No test is rewritten or
   parameterized to dodge this — the suite simply never consumed asset files.
2. **f16 intensity ceiling is a hard parser constraint.**
   `EquirectImage::decode_hdr` (`ibl.rs:232-241`) is `image::open` (image
   crate 0.25, Radiance decoder: accepts `#?RADIANCE`/`#?RGBE` magic,
   `32-bit_rle_rgbe`, `-Y h +X w`) followed by **f32→f16 conversion** —
   values above 65504 become Inf in the IBL bake. Sun injection hard-clamps
   at **30000** (kloppenheim's real peak of 36416 already round-trips today,
   so 30000 keeps margin without losing anything the engine can use).
3. **Diffusion360's RealESRGAN stage is dropped and its package `__init__` is
   bypassed** (see env decision): `txt2panoimg/__init__.py` transitively
   imports `realesrgan` at module load, so A2.5's runner loads
   `pipeline_base.py`/`pipeline_sr.py` directly via
   `importlib.util.spec_from_file_location` — using two self-contained
   Apache-2.0 modules as published, skipping an optional upscaler we don't
   want, not patching their code.
4. **Path 3 does not txt2img at 2048×1024 directly.** A1's proven lesson:
   SDXL degrades past its native area budget. Native generation is
   **1536×768** (a 2:1 shape the sdxl-360 model card itself recommends,
   area ≈ SDXL native), then one whole-canvas img2img hop to 2048×1024 with
   the A1-proven recipe (strength 0.35, 40 steps, gs 7.0,
   `enable_model_cpu_offload()` mandatory) — circular-x padding active in
   both passes.
5. **`turntable` gets an `--hdri` flag** (A2.1). The bin hardcodes
   `const HDRI: &str = ".../evening_road_01_puresky_2k.hdr"` — reviewing
   DamagedHelmet under a *generated* environment is this phase's whole
   verify loop, so the environment becomes an optional flag (default
   unchanged).
6. **Sun direction is IBL/sky-only; the engine's shadow sun is separate.**
   The directional light + shadow pass come from the engine's own light
   state (zone/`set_light`), not the HDRI. The injected sun disc feeds IBL
   energy and the visible sky; its azimuth/elevation is recorded in the
   manifest so Phase B2 can align the zone light direction with the baked
   sun. No renderer change needed or made.

- [x] **A2.2 — `hdr_post.py`: LDR equirect → game-ready Radiance `.hdr`** `[fable]` — done 2026-07-18 (committed 2a6653c; engine round-trip green, seam MAD 0.0021 inside reference band; opencv-python-headless 5.0.0.93 added to StableMaterials venv).

  The shared post stage all three paths feed. Runs in the StableMaterials
  venv; first step: `C:\tools\StableMaterials\venv\Scripts\python.exe -m pip
  install opencv-python-headless` (record the installed version for A2.11).

  **RGBE writer decision (made at planning, verified on this machine):**
  `cv2.imwrite("<out>.hdr", float32_bgr)` — writes `#?RADIANCE` /
  `FORMAT=32-bit_rle_rgbe` / `-Y h +X w`, exactly what the image crate's 0.25
  decoder behind `EquirectImage::decode_hdr` accepts; round-trip measured at
  ~0.4% median relative error with a 30000 peak. No imageio (needs a
  freeimage binary download), no hand-rolled RGBE encoder (cv2 is already
  battle-tested; fall back to a manual numpy RGBE encoder only if cv2
  surprises — evidenced, not speculative).

  CLI: `hdr_post.py <ldr.png> --out <file.hdr> [--sun auto|AZ,EL|none]
  [--sun-intensity N] [--seed-manifest <generation_manifest.json>]`.
  Pipeline, in order:
  1. **Load + shape gate:** input must be (or is Lanczos-resized to)
     2048×1024; assert exact 2:1.
  2. **Linearize:** exact sRGB→linear EOTF (not a 2.2 approximation).
  3. **Highlight expansion:** a monotonic, order-preserving curve lifting
     the top of the range into HDR — anchored to the measured references
     (table above): a lit dusk sky should land near evening_road's register
     (median ~0.5, p99.9 ~9, cloud/glow peaks ~20); an overcast sky lower.
     Exact curve is this task's design call — constraints are monotonicity,
     no banding, and the anchor stats; document the chosen curve in the
     manifest.
  4. **Wrap-seam blend:** cosine cross-blend over the last ~32 columns onto
     the first (Diffusion360 and path 3 are seam-aware by construction;
     path 1 is not — this normalizes all three). Target: seam MAD ≤ 0.02
     linear (references sit at 0.003–0.006).
  5. **Sun-disc injection** (skipped under `--sun none`): position from
     `--sun AZ,EL` (degrees) or `auto` = centroid of the brightest
     above-horizon region of the expanded sky. Physically-shaped core
     (~0.5–1° angular radius at equirect pixel scale) + gaussian glow
     falloff; `--sun-intensity` default ~2000 (design call to tune against
     the A2.7 helmet renders; kloppenheim's 36k hard sun and evening_road's
     soft 20 bracket the plausible range). **Hard clamp 30000** — divergence
     2's f16 ceiling. Record resolved azimuth/elevation in the manifest
     (B2 aligns the zone light direction to it).
  6. **Self-checks, printed PASS/FAIL per check, any FAIL exits 1:** dims
     exactly 2:1; all values finite and ≥ 0; peak ≤ 30000; median within
     [0.02, 2.0]; wrap-seam MAD ≤ 0.02.
  7. **Write** `<out>.hdr` via cv2 (RGB→BGR order!) + `<out
     stem>.manifest.json`: source file + sha256, upstream
     `generation_manifest.json` contents if `--seed-manifest` given (chains
     provenance from the generation step), every parameter incl. resolved
     sun az/el and the expansion curve, output stats (peak/median/mean/seam
     MAD), cv2/numpy versions — same reproducible-from-manifest contract as
     `gen_material.py`.

  **Verify (foreground, like every command in this file):** build a
  synthetic 512×256 sky-gradient PNG inline (bright band near horizon, dark
  zenith), run `hdr_post.py` on it with `--sun 90,10`; exits 0, all
  self-checks PASS, output + manifest exist. Then the engine round-trip:
  ```
  cargo run -p engine-renderer --release --features offscreen --bin turntable -- content/source/test/DamagedHelmet.glb --out target/hdrpost-smoke --angles 4 --size 256x256 --hdri <synthetic-out>.hdr
  ```
  exits 0, frames > 2 KB — proves decode_hdr, the f16 upload, and the IBL
  bake all accept the writer's output *before* any GPU generation is spent.

  **Files:** `scripts/ai-pipeline/hdr_post.py` (new).

  **Circular-padding mechanism (concrete, from code read at planning):**
  StableMaterials' own `pipeline.py:319-353` (on disk at
  `C:\tools\StableMaterials\weights\pipeline.py`) proves the trick in this
  exact venv: a `@contextlib.contextmanager` that monkeypatches
  `torch.nn.Conv2d.forward` globally — random roll, `F.pad(x, (4,4,4,4),
  mode="circular")`, original forward, proportional crop, unroll. The x-only
  adaptation: roll in x only; `x = F.pad(x, (pad, pad, 0, 0),
  mode="circular")` (y keeps the conv's native zero padding — `orig_forward`
  still applies it); crop `int(pad * factor)` from x only; unroll x. Wrap
  **both the txt2img call and the img2img hop and their VAE decodes** in the
  context so latent and pixel space both wrap (the global patch covers the
  VAE automatically while active). Torch's built-in
  `padding_mode='circular'` on Conv2d is both-axes and constructor-level —
  the forward patch is the correct x-only lever.
