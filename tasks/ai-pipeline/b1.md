# Phase B1 — Direction Lock: docs + lore reskin (subplan)

Source: `zesty-bubbling-acorn.md`, Plan B / Phase B1, planned 2026-07-23.
Locks the Castilian/Andalusian religious dark-fantasy direction in the two
places later phases read it from — `docs/visual-quality.md` (the machine- and
eyeball-checked quality bar) and the content/tasks docs that B2–B5 planners
consume. **Docs + strings only: no generation runs, no GPU, no code, no
model/palette/zone changes** (palette code is B5, zones are B2).

This file breaks the phase into 4 single-agent tasks plus the gate. The
orchestrator dispatches one agent per task, verifies with the given command
(never prose), commits on green, and strikes the checkbox. B1.1 lands first —
its rewritten text is the vocabulary source for B1.2/B1.3; B1.2–B1.4 are then
independent and dispatchable in any order.

Tiers (routing table, campaign plan): **fable** = art-direction judgment
(here: the visual-quality.md rewrite — new HSV ranges and lighting-mood
language are direction calls, not transcription); **sonnet** = lore/comment
reskins and plan-doc updates. Nothing here is haiku-worthy; gate bookkeeping
is the orchestrator's.

## Direction being locked (from the campaign plan — the workers' brief)

Castilian/Andalusian religious dark fantasy: sun-bleached and soot-darkened
stone, gothic-baroque cathedral ruins, votive candles, gilded altarpiece
fragments, wrought iron, processional/penitent imagery, dry olive-and-cypress
plateau under low amber dusk. Render register **unchanged**: semi-realistic
PBR, Diablo IV / Path of Exile 2 — explicitly not Blasphemous's 2D style.
Color language (proposal — the user tunes numbers at the phase-gate text
review): ambient world desaturated warm stone; environmental emissive =
candle-gold; player VFX = pale votive blue-white "cold flame" (keeps the
cool-vs-warm legibility split); threat/telegraph stays red-orange→crimson.
**Names and identifiers do not change** (races, classes, zones, chapters,
damage types `Runes`/`Divine`/`Corrupt` — locked user ruling).

## Probed facts and divergences (2026-07-23 — flagged per project policy)

1. **No `description`/lore fields exist in any RON.** The campaign plan says
   "reskin descriptions in race/class/chapter RONs"; probing all of
   `content/races/*.ron`, `content/classes/*.ron`,
   `content/chapters/*/chapter.ron` shows the Nordic register lives entirely
   in `//` header/flavor comments (elf: "keeper of the World Tree's roots";
   dwarf: "mountain-forged"; valkyrie: "warrior-maiden"). The only parsed
   strings are ids/names/clip names — all locked. So the reskin is a
   **comment rewrite**, and "byte-identical outside description strings"
   becomes "byte-identical outside full-line `//` comment lines," which the
   B1.2 verify asserts mechanically from the diff.
2. **VQ-A values are machine-checked nowhere.** Workspace grep for `VQ-A`:
   every hit is a comment (presentation.rs, telegraph.rs, zones.ron,
   bolt.ron, ember_bolt.ron), an allowlist pin
   (`scripts/lint-comments-allowlist.txt`), or one assert *message string*
   (`ground_render.rs:52`, cites VQ-A2, no numeric coupling). No test or lint
   consumes VQ-A4's HSV numbers. Rewriting VQ-A1/A4/A5 breaks no machine
   gate; only the **clause ids** must survive, because those comments and
   allowlist pins cite them. B1 changes no source comments, so
   `lint-comments.sh` (scope: crate dirs only, content/ and docs/ excluded)
   and its allowlist are untouched.
3. **Chapter RONs carry almost no Nordic register.** `chapter.ron` comments
   are camp-layout mechanics plus neutral flavor ("meadow pack"); the flavor
   `name:` fields ("Chapter 1 — First Field", "Chapter 2 — Emberwood Rest")
   are names and stay. **Enemy/NPC prefab comments (sentinel, cinder_imp,
   grunt, npc_elder…) stay untouched**: they describe the placeholder SDF
   blobs accurately, enemies are explicitly pre-content placeholders, and
   real enemy design will replace them wholesale — theming their comments
   now would be invented scope.
4. **`CHARACTER-SYSTEM.md` does not exist in the repo** but is cited by
   `content/classes/ravager.ron:1` (and by `stats.rs`/`buff.rs` comments —
   source files, out of B1 scope, logged for the ledger). B1.2 rewrites
   ravager's header line anyway and drops the dangling pointer there.
5. **Stale-claim nit inside the doc under edit:** `docs/visual-quality.md`
   VQ-B1 names its test `races_render_as_rigged_meshes`; the real test is
   `race_clips_exist_in_gltf` (recorded in a4.md's contract probe). B1.1 is
   already rewriting this doc — the comment policy forbids stale claims, so
   the one-word test-name fix rides along, explicitly scoped to that name.
6. **Wording drift accepted until B5:** `content/prefabs/bolt.ron` ("cool
   arcane (VQ-A4)") and `client/vordar-client/src/telegraph.rs` cite VQ-A4
   *roles*, which survive the rewrite (player VFX stays a cool role, threat
   stays red-orange). The word "arcane" vs the new "votive" register drifts
   until B5's VFX/palette pass retunes those files — noted, not patched here.
