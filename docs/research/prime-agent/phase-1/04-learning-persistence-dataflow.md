**Baseline:** user-authorized Prime Intellect PRIME Agent `v0.7.0`, commit `be9e2fa0714e7cd1c6bd9bdb1b554d2cc6550387` (tree `0625a8fd0550a8de7ff05e8d9248e75563e5b520`). P1's binding of the 2026-08-05 launch to a unique revision remains **UNRESOLVED**. **Audit/retrieval date:** 2026-08-06. Public, read-only first-party source only; no package/product acquisition, service/API call, account, episode, training, or recovery execution. P3 permits this analysis but remains **BLOCKED** for execution.

## Central verdict

**Durable cross-episode learning is source-demonstrated only in a narrow product-local sense:** an explicitly **global** refinement can turn the current session's message trajectory into CRUD edits to named JSON records (`prompt`, `memory`, `skill`, or `subagent`), persist them in `~/.prime/agent/harness/harness_state.json`, and inject a compact rendering of those records into a later session's system prompt. [S4][S5] This is durable **supplemental context adaptation**, not model training. The baseline does not update model weights, optimizer state, a learned policy object, or the immutable base system prompt; does not install executable skill code through `/refine`; and has no source-demonstrated reward-to-update pipeline. “Outcome” is the refiner model's expected-outcome text, not an observed reward. [S4]

That narrow chain is **not source-demonstrated as crash-safe, exactly once, or improving**. State, global history, and session history are three sequential writes without a transaction; state writes lack an evidenced file+directory `fsync`; direct Python harness writes truncate the target in place; JSONL tails and corrupt state are silently skipped/degraded to empty; auto-refine failures can merely enter cooldown; and no durable refinement request/reward/checkpoint identity closes immediate retry. [S3][S4][S8] A later prompt can contain a saved entry, but source cannot prove the model attends to, follows, or improves from it. No empirical improvement is claimed.

## Node/edge dataflow

```text
N1 task input (text/images; session/client command)
  --E1 normalize/admit--> N2 AgentSession queue
  --E2 user message--> N3 agent loop context + system prompt
  --E3 provider call--> N4 remote selected model
  --E4 assistant toolCall--> N5 IPython/tool process OR N6 RLM child AgentSession
  --E5 toolResult / explicit child message / referenced files--> N3 next model turn
  --E6 message_end append--> P1 session <session-id>.jsonl + child/artifact dirs

Manual /refine or refine.run, or automatic root-session trigger
  --E7 review inputs--> N7 model review gate (auto only)
  --E8 plan inputs--> N8 model JSON proposal
  --E9 validate/re-read/apply--> N9 HarnessState in memory
  --E10 save--> P2 local <session-artifact>/harness/harness_state.json
                  OR P3 global ~/.prime/agent/harness/harness_state.json
  --E11 sequential audit writes--> P4 global refinements.jsonl (global only)
                                  + P1 custom prime-agent.refinement entry
  --E12 rebuild/load/merge/format--> N10 current or later session system prompt
  --E13 ordinary provider inference--> N4 later response/action
```

## Reward/outcome attribution

There is **no source-demonstrated reward producer→persisted reward→updater consumer chain**. The trajectory contains model/tool messages and errors, and can contain externally produced metric/judge text if a tool/user inserts it, but no required reward schema, scalar/objective identity, provenance, or consumer selects such a record. `proposal.rationale` and `proposal.expectedOutcome` are produced by the refiner model itself; `applyRefinementProposal` copies them to event `evidence` and `outcome` before any later validation. [S4] Consequently:

```text
observed task/tool messages -> model-authored rationale + expectedOutcome
                            -> harness event text
                            -X-> no reward optimizer / no observed-outcome updater
```

Replay is likewise not learning. Session reload reconstitutes conversation context; daemon cursor replay resynchronizes clients; neither updates a policy. [S3][S9] A quality gate or external judge can be part of transcript text, but source does not make it a priced reward or bind it to the changed entry and later matched result.

## `/refine`, automatic trigger, bypasses, and rollback

1. **Manual command / kernel skill:** `/refine` invokes the host path; `await refine.run()` only queues one request to run after the current cell/turn and returns scheduled/not-scheduled. Local is default; global requires explicit request. [S11]
2. **Automatic path:** interval/post-compaction review is opportunistic, root-only and local by default. Reviewer rejection, disabled settings, cooldown, missing model, non-persisted/child sessions, branch invalidation, or planning/application failure bypasses publication. Interactive review/refine catches can only stamp cooldown; the source does not persist a durable skipped/failed auto-review outcome. [S2]
3. **Direct `rlm.harness` bypass:** kernel code can CRUD local/global harness JSON directly, bypassing trajectory review, proposal snapshots, global refinement JSONL, and session refinement result unless it separately calls `record_refinement`. It uses mtime reload, not a lock. [S8]
4. **Corruption fallback:** TS and Python loaders treat unreadable/corrupt/non-object state as empty; malformed history/session JSONL lines are skipped. The next save may replace lost state with an empty/new state. This is a **source-demonstrated silent bypass of learning**, not graceful recovery. [S3][S4][S8]
5. **Rollback:** `/refine --rollback <id>` (or equivalent host option) finds history, reverses applied edits using recorded `before`/`after`, and publishes a new refinement with `rollbackOf`; it does not restore a byte-level checkpoint. Local rollback depends on the same session's custom JSONL result and recorded state path; global rollback depends on global/session merged history. Missing state/history, malformed skipped lines, concurrent change, or missing entry can fail/partially apply. [S2][S4]

| Path | Orderly shutdown | Abrupt process/host death; restart and retry | Classification |
|---|---|---|---|

[S2] | Partial model stream becomes aborted only if live abort handling runs; hard death may leave no terminal message. | Harness bytes | Host state uses temp+rename; direct Python CRUD uses `open("w")` on target. No source calls fsync for either state path. | Duplicate/immediate retry | One live session serializes refines and baseline-checks touched entries; branch version rejects stale plans. A new retry can create a new proposal: create may report exists; update/delete may reapply/fail; global cross-session races can overwrite. | Machine restart order | No core database, broker, container, or local weight server is present. Filesystem/Prime state must be available; operator starts CLI, which starts/adopts supervisor→catalog/worker→loads session and global/local harness→rebuilds prompt; provider/auth/network precede inference; Python environment/kernel restore and child rehydration follow if used. [S5][S7][S9][S12] | No OS boot service/container orchestrator is supplied. Abrupt host recovery, actual bytes, remote provider request outcome, and optional Prime-hosted service ordering are untested/opaque. | local order **demonstrated by source** at process level; restart correctness **unknown** |

**Scope and retention:** local state lives under a persisted session artifact directory and affects that session on resume; ephemeral/non-persisted sessions cannot local-refine. Global state lives under the Prime agent directory and affects unrelated later sessions for the same configured agent directory/OS account. No project key, task/episode match key, model revision, expiry, maximum store size, reward ID, trajectory hash, or artifact hash is part of the harness schema. [S4][S8] Global therefore means agent-directory-wide, not “matched Vordar episode”; project qualification is only model-authored text policy.

## Phase-2 evidence still required

Source demonstrates mechanism existence, not causal magnitude or improvement. Phase 2 must use an already-on-disk real Vordar artifact/task—not a synthetic demonstration—and independently bind: task/session ID; exact input/artifact hashes; model/provider revision; complete tool/child trajectories; external priced-outcome producer; reward record and provenance; refinement ID plus before/after harness bytes; and the later fresh-session prompt/action/result consuming the same global entry. It must show that the check reads the bytes the later inference receives and first prove red when the load/use edge is broken.

Recovery evidence must exercise orderly shutdown and hard worker/host death at pre-plan, in-plan, pre-rename, post-rename/pre-history, and post-history boundaries; inspect state/history/session bytes; restart after downtime in the source-required order; immediately retry with same and new command identity; and require an explicit zero/one/duplicate outcome. It must also exercise corrupt/torn files, silent-empty fallback, concurrent global refinements, Pi/Prime directory separation, and optional-service unavailability without allowing learning to disappear silently. If hosted training is considered, first obtain immutable service/data/reward/checkpoint schemas and prove checkpoint publication, rollback, restart retention, and exact later model loading; current source supplies none. These are phase-2 gates, not a pilot design or an adoption decision.
