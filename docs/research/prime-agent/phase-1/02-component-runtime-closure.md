# PRIME Agent component and runtime closure

**Authorized baseline only:** Prime Intellect PRIME Agent `v0.7.0`, commit `be9e2fa0714e7cd1c6bd9bdb1b554d2cc6550387` (tree `0625a8fd0550a8de7ff05e8d9248e75563e5b520`). All findings below apply only to this user-authorized baseline. P1's historical binding of the 2026-08-05 launch article to a unique release/commit remains **UNRESOLVED**; this report does not identify this commit as the launch revision. No installation, artifact acquisition, clone, resolution, authentication, service call, or execution was performed.

**Audit / retrieval date:** 2026-08-06. All code citations are first-party, immutable commit-SHA permalinks (tier 1). The GitHub tree API and P1 release metadata were also read on that date.

## Enumeration method and limits

1. Enumerated the complete commit tree through GitHub's recursive tree API: 1,281 entries (1,133 blobs, 148 trees), `truncated:false`; selected every manifest/lock, executable/bin, lifecycle/process, persistence, network/provider, RLM/Python, refinement, installer/update, sandbox/container, telemetry, queue, and service path. [S1]
2. Parsed the root `package-lock.json` as JSON without resolving it. Reproducible count: `len(packages)=445`; nine workspace manifest records; of the remaining 436 install-path records, eight are workspace links and 428 are external versioned package paths. All 428 have `version`; 169 records also have both `resolved` + `integrity`, while 259 omit one or both and therefore do not individually name immutable package bytes. [S2]
3. Enumerated all nine npm workspace manifests, all 12 non-test Python `pyproject.toml` files (runtime plus 11 Python-backed skills), all 13 bundled skill directories, all runtime CLI modes/public commands, and every source-discovered subprocess class. [S1-S6]
4. Counted the committed generated catalog by exact syntactic fields: 1,162 `provider:` model records, 32 distinct provider IDs, and 38 distinct literal `baseUrl` values. This is a committed snapshot, not a weight lock. [S7]
5. Searched the complete tree path list for `Dockerfile`, Compose manifests, container manifests, image references/digests, Python locks, and alternate JS locks. None exists. The only npm authority is root lock blob `909fda27b6f2846b4355433dda7f500bb72a5f1b`; three example-only nested npm locks also exist. [S1]
6. Read-only web cannot inspect the P1-recorded release tarballs, invoke package resolution, inspect hosted services/models, or exercise power-loss recovery. Therefore absence means absent from the exact source tree/evidenced product path, not impossible through arbitrary model-generated shell code or dynamically installed packages.

## Docker/container verdict

The exact tree contains no Dockerfile, Compose file, OCI manifest, image reference/digest, container launcher, or Docker recovery path. Core execution is explicitly same-user unsandboxed IPython/shell. Therefore Docker is **not required, not supplied, and not evidenced as a supported core recovery layer** for this baseline. The optional sandbox example uses macOS `sandbox-exec` or Linux bubblewrap, not Docker; the optional `prime-intellect` skill can dynamically install another CLI and request remote Docker sandboxes, whose images/services are unpinned. Arbitrary shell can invoke host Docker if separately installed, but that is user/model-acquired state outside the product graph. [S1][S11][S15][S20]

## Intermittent-host shutdown/restart disposition

Orderly path: `prime-agent shutdown` -> reject new mutations -> checkpoint/update preparation when applicable -> stop workers/descendants/kernels -> stop catalog/supervisor; force path kills unresponsive process groups/tracked children. [S10]

Abrupt process path: a worker crash is retried and old known process trees are reaped; a supervisor loss can be replaced by a worker; command and worker journals expose completed versus uncertain work and avoid replaying uncertain side effects. [S10]

Abrupt host-power path remains unevidenced. On power return there is no installed OS boot service/container: an operator/client must launch EP1, which starts N2, loads ownership/descriptors/journals, starts N3, adopts or recovers N4, restores N5/P2, then lazily provisions/restores N7. Remote N6/N12/N14 and credentials must be available before retry. Session JSONL appends and several artifact/history writes lack an evidenced fsync+directory-fsync transaction; kernel snapshots are best-effort and skip unpicklable values. An in-flight provider request, shell side effect, refine plan, queue item, trace upload, or package update can therefore be lost, duplicated externally, or only marked uncertain. Missed schedules are coalesced/advanced rather than replayed, so downtime work is not recovered as if it ran. Source claims do not replace the required phase-2 impolite-path test.
