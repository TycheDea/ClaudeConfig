# PRIME Agent multimodal and visual-support closure

**Baseline:** user-authorized Prime Intellect PRIME Agent `v0.7.0`, commit `be9e2fa0714e7cd1c6bd9bdb1b554d2cc6550387` (tree `0625a8fd0550a8de7ff05e8d9248e75563e5b520`). P1's launch-revision binding remains **UNRESOLVED**. **Audit/retrieval date:** 2026-08-06. Public read-only exact-commit source only; no image/model/render/service execution or Vordar-asset access.

## Central verdict

PRIME has **native still-image transport to a selected remote vision model**: it represents base64 image bytes as `ImageContent`, persists them in ordinary user/tool-result messages, and its provider adapters place those bytes directly in provider-bound image fields. This is native only when the selected model's exact catalog record includes `input: ["text", "image"]`; otherwise images are removed or replaced by text. It is not local vision and does not prove the opaque hosted model's behavior. [S1][S8-S11]

PRIME has **no native screenshot/render capture, video/temporal representation, visual comparator, independent-judge protocol, visual reward, or image-output message type**. Its IPython/`%%bash` surface can compose operator-supplied renderers, pixel scripts, services, and file outputs, and `attach_image` can then feed stills back to a vision model. That is tool-mediated composition, not built-in visual understanding or evaluation. [S1][S6-S7][S15]

Therefore the frozen Vordar visual-asset pilot is **not source-ready for evaluation under existing visual law using PRIME alone**. A separate Sol visual judge can remain organizationally outside PRIME/frame production, and the authorized catalog does mark `openai-codex/gpt-5.6-sol` image-capable, but PRIME neither enforces that separation nor binds the judge to persisted reviewed-byte identities. Phase 2 still needs evidence for exact frame hashes, required gameplay framings, independent producer/judge identities, verdict/reward linkage, red proofs, retention, and impolite-path recovery. This is an evidence gap, not an adapter or adoption decision. [S11-S14][P4][P5][V1-V5]

## Classification

`native` = exact-baseline code sends image bytes to a provider-bound model input. `composable` = a user/extension/external tool can create or inspect data, but PRIME supplies no semantic visual guarantee. `metadata-only` = path/name/MIME/labels without model-bound image bytes. `absent` = no baseline type/producer/consumer for the property.

## End-to-end visual data paths and boundaries

### A. User/file still → native remote vision

```text
operator/client-owned file or clipboard bytes
  -> Prime client/attach-image local sniff/decode/optional resize
  -> ImageContent {base64,mimeType}
  -> local daemon IPC / worker queue
  -> Agent user or toolResult message
  -> model.input image gate + block-images policy
  -> provider adapter image field
  -> HTTPS provider/service-owned model
  -> text/tool-call assistant result
  -> local session JSONL; optional HTML/export/trace upload
```

Ownership changes at local ingestion (operator bytes → Prime-produced resized bytes), local worker/session state, and remote model service. `images.blockImages=true` replaces all provider-bound images with `Image reading is disabled`; `showImages` controls terminal presentation only and is not perception. [S12]

### B. Tool-produced frame → inspection

```text
external/project renderer or screenshot command (user-composed; host/service-owned)
  -> output file (tool/project-owned; no Prime artifact identity)
  -> attach_image or CLI ingestion
  -> Path A
```

The baseline supplies only the second arrow. An external command may also upload data or call a hosted renderer; that egress, credential, output rights, completion/idempotency, and service retention belong to the chosen external component, not PRIME. No renderer/screenshot/browser service is silently implied by filesystem access. [S6-S7][S15]

### C. Persistence and egress

A `SessionMessageEntry` stores the complete `AgentMessage`; persistence uses `JSON.stringify(entry)` in session JSONL, so accepted user/tool image base64 is inline rather than a content-addressed blob. HTML export JSON-serializes and base64-wraps the full session data. Opt-in Prime Traces reads the raw NDJSON and PUTs it to the configured remote endpoint, but refuses files over 20 MiB; image-heavy sessions can therefore be locally persistent yet non-uploadable. [S14]

No image record has a digest. `attach_image` records a source path in tool details; resized bytes may no longer equal that file. Daemon artifact IDs hash `(sessionId,type,filePath)`, not content. There is no frame-set ID, camera/view label, producer build, source/output hash pair, judge ID, verdict ID, or reward link. Thus persisted inline bytes are hashable after the fact, but PRIME does not persist **which exact bytes an independent judge reviewed** or bind that identity to a verdict. [S6][S13-S14][P5]

## Shutdown, restart, and recovery

- Before submit, pasted-image bytes live only in the bounded client registry; client/process death loses them. Accepted user images may also remain unwritten until an assistant exists because ordinary session persistence defers pre-assistant entries. [S4][S14]
- Completed JSONL entries can restore inline images, but appends have no evidenced fsync/checksum; malformed lines are skipped. Abrupt death can leave no terminal provider/tool result, while the provider may have received bytes. Immediate retry has no image/request digest or remote idempotency proof. [P5]
- `attach_image` source validation and emission are not transactional with session append. Death can leave a changed source path, a provider-received image without a durable tool result, or a durable resized image with no source-byte hash. Kernel attachments not yet converted into a persisted tool result are volatile. [S6-S7][P5]
- On restart, valid persisted messages can be resumed and resent on a later inference, but that is non-deterministic session continuation, not visual replay. No mechanism re-runs a renderer, reconstructs a temporal frame set, verifies stored image bytes, reconciles a provider request, or resumes a judge decision. Pending trace upload is not recovery authority. [P5]

## Vordar visual-law fit and phase-2 gaps

Existing law requires headless in-engine evidence under destination lighting, gameplay-camera close-up, player-for-scale frame, retained outputs, metrics only as pre-screen, explicit crispness, and an independent Sol judge separate from production; checks must read the shipped/reviewed bytes and first fail on broken input. [V1-V5]

**Fit:** PRIME can carry the required still frames to a vision-capable Sol model, and its architecture does not require the producer to self-judge. Therefore external separation remains possible. Baseline source does **not** establish compliance: multi-image input is not a framing manifest; model vision is not an independent verdict; path/MIME is not byte identity; a self-authored metric or producer-model opinion is not reward; terminal image rendering is not in-engine evidence.

**Phase-2 evidence gaps (no design or run authorized):** exact frozen real-task/input hashes; source/render/reviewed-byte hash chain; headless renderer identity and retained output paths; camera/lighting/player-scale/view labels; no-op and corruption red proofs reading the actual reviewed bytes; separate producer and Sol-judge process/session/model/credential identities; verdict-only schema tied to every frame hash; metrics/judge/reward provenance and later-learning linkage; provider format/quota/retention/service terms; disabled trace/external egress or explicit approved boundaries; and orderly plus abrupt-death/restart tests proving frame, trajectory, verdict, and retry disposition without Pi/Prime state mixing. Until those gaps close, result is **NOT SOURCE-SATISFIED FOR A VORDAR VISUAL-ASSET PILOT**.
