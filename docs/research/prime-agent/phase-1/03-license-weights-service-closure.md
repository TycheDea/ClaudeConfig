# PRIME Agent license, weights, datasets, and service-terms closure

**Baseline:** user-authorized Prime Intellect PRIME Agent `v0.7.0`, commit `be9e2fa0714e7cd1c6bd9bdb1b554d2cc6550387` (tree `0625a8fd0550a8de7ff05e8d9248e75563e5b520`). This is not evidence that the baseline was the unresolved 2026-08-05 launch revision (P1 remains `UNRESOLVED`).

**Audit/retrieval date:** 2026-08-06 for every mutable legal/service page. Immutable source was read only at the commit above. No product/package/model artifact was acquired, no terms were accepted, and no account or service was used. This is a technical rights/provenance inventory, not legal advice and not an adoption decision.

## Result in one sentence

The commit's own source is MIT, but execution rights do **not** close: the exact release package contents and installed npm graph are unavailable; pi-derived provenance has no exact upstream base or immutable file comparison; Python, managed-tool, extension, container, model/weight, provider, OAuth/MCP, telemetry, and Prime-hosted service terms contain unpinned or opaque execution-relevant artifacts. Under Vordar's standing strict-NC rule, none of those unknown paths or their outputs may enter a shipping-asset path.

## Decision vocabulary and standing constraints

`compatible` means the cited artifact, by itself, exposes no conflict with Vordar's existing commercial/strict-NC rule; it is not a legal opinion. `blocked` means the artifact cannot enter the proposed execution/shipping path on current evidence. `unknown` means primary evidence is missing or cannot bind to an exact artifact. `not applicable` means the class is absent or disabled for the stated path.

The standing rulings are unchanged: (1) NC software may be used for evaluation only, but neither it nor its outputs may touch a shipping path; (2) a clean repository LICENSE is not provenance proof, so derived/vendored source must be compared to upstream; (3) code, package metadata, service terms, model cards, and weight licenses are separate evidence objects; (4) incumbent compatibility is not a license gate; and (5) every route to a claimed guarantee must be enumerated. ## Vendored/derived upstream comparison

Prime's exact LICENSE preserves Mario Zechner's MIT notice and its README says the agent/TUI is built on pi; exact docs call it a hard fork. The GitHub repository reports `fork:false`. No baseline file identifies an upstream repository revision, fork-base commit, vendored-file manifest, or later upstream cherry-picks. The current `badlogic/pi-mono` and `earendil-works/pi` LICENSE bytes match the Mario-only portion, but mutable current license equality neither identifies inherited files nor proves that every inherited/modified file was MIT at import.

A qualifying comparison needs: (a) first-party exact upstream repository + full commit SHA at fork, (b) a baseline-to-upstream path map, (c) immutable byte diffs for every inherited/vendored module, including headers and removed notices, (d) later imported commit SHAs, and (e) release-package confirmation that L1 travels with substantial copies. Until then, pi lineage is `unknown` and prevents a provenance-complete shipping-path conclusion.

## Required versus optional and Vordar implications

For the proposed self-improving RLM pilot, required classes are L1-covered Prime source/release, Node/npm installation, N1-N7/N9 core process path, one N6 provider/model/output regime, Python runtime/build graph, and local P1-P6/P8 stores. They are not execution-closed because the shipped npm graph, Python graph, pi provenance and selected provider/model/weight terms are unknown. Optional classes are managed search tools (default preload but degradable), extensions/packages, MCP, OAuth alternatives, remote traces, Prime platform skill/services, local/remote sandbox, custom/local models and hosted datasets/training. Optional does not mean harmless: each is `not applicable` only after the pilot configuration disables it and evidence confirms no fallback/dynamic acquisition can reactivate it.

Strict NC exclusion is the only standing toolchain gate; incumbent Pi compatibility is merely cost. L1 is not NC, and L3's metadata contains no explicit NC label, but metadata/absence is not raw-license proof. Therefore no unknown transitive, dynamic, hosted, base-model, dataset or tool component—and no output it helps produce—may enter a Vordar shipping path. Public read-only P4 analysis can continue without executing/accepting terms. An eval-only, non-shipping pilot still requires user approval and selected service terms, credentials, sandbox and provenance gates; this report neither authorizes nor designs it.
